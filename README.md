# Agent ID Radar · 沐光

BSC Agent ID 项目扫描、交易规则检查、预算记账与独立底仓管理。

**当前为 0.1.0-beta.1 开发预览版，默认观察／模拟。没有连接或使用维护者的钱包测试真实交易。**

第一版把发现项目和付款执行分开：扫描可以持续运行；未知合约只记录和提醒；自动参与需要本地审核模板。规则检查失败就停止该笔操作，不通过猜测补齐数据。

## 先运行演示

需要 Node.js 22 或更高版本，不需要安装第三方 npm 依赖。

Windows 用户下载本仓库 ZIP 并解压，双击 **双击运行演示.bat**。它只运行本地合成场景，不连接钱包、不调用区块链。

也可以运行：

~~~sh
npm test
npm run check
npm run demo
~~~

演示包含三种情况：

- 免费币先回撤、次日上涨：普通退出只卖交易仓，保留 30% 原始数量。
- 付费币回本后回撤：实际回本后，把剩余数量的一半固定为底仓。
- 付费币没有回本且继续下跌：保留原来的风险退出条件。

演示中的价格、费用和流动性都是明确假设，不能当作历史回测或收益证明。

## 启动只读扫描

1. 双击 **双击启动观察.bat**。首次会生成并打开 config.json。
2. 在 rpcs 中填写自己使用的 HTTPS BSC RPC，保持 mode 为 shadow。
3. 保存配置，再次双击。未知项目只观察，不会自动付款。

命令行等价操作：

~~~sh
node src/cli.mjs init
node src/cli.mjs check
node src/cli.mjs watch
node src/cli.mjs status
~~~

未配置钱包也可以做项目发现。配置钱包地址后仍不代表允许付款；没有审核模板的项目继续只观察。

模板需要逐个审核合约和代币代码、权限、铸造调用、退款条款、偿付资金和池子状态，见 [模板说明](docs/templates.md)。代码指纹可以用以下只读命令查看：

~~~sh
node src/cli.mjs inspect 0x实际合约地址
~~~

**指纹只标识被审核的代码版本，不能自动证明项目安全或资产价值。**

## 已实现的执行限制

| 项目 | 默认规则 |
| --- | --- |
| 付款入口 | 铸造、授权、撤销授权和卖出使用同一个执行网关 |
| 单项目 | 每钱包累计不超过 12 USDT 等值，审核模板固定数量／付款 |
| 新增买入日预算 | 所有钱包合计 0.05 BNB 等值，同时检查每钱包上限；北京时间自然日 |
| 临时预算 | 必须有明确失效时间，最多 0.08 BNB，到期恢复 |
| 自动 Gas | 每笔最多预占 0.001 BNB；全天所有自动操作累计 Gas 预算 0.01 BNB |
| 免费铸造 Gas | 每钱包每天最多 0.005 BNB；最多 1000 笔，受全局预算共同限制 |
| 钱包预留 | 新买入／铸造后至少预留 0.006 BNB，供退出和授权清理使用 |
| 付费 NFT | 自动参与关闭；免费 ERC721 只有审核模板明确匹配时才可规划 |
| 权限 | 禁止意外授权、账户权限变化、非预期资产扣减 |
| 收货 | 预演与回执都核对预期资产；收到其他垃圾资产不能代替 |
| 退款 | 本地审核约束、链上期限／资金覆盖复核；缺失则不自动付款 |
| 重复执行 | 单进程锁、钱包串行、发送前预算预占、未确认交易持续锁定 |
| 更新 | 没有自动下载、安装或更新功能 |
| 聊天 | 仅可选的 TG 纯文本通知，没有群聊交易命令入口 |

手续费型“免费”铸造也视为付费。观察模式同样检查预算，但不生成真钱订单，也不把影子计划伪装为成交。

Gas 预占会在广播前与签名交易封装中的 gas 上限核对。真实广播要求官方 CLI 提供能核对的钱包、目标、金额、调用数据、链 ID、nonce 和最高 Gas 字段。**该协议尚未进行真实钱包兼容测试；CLI 返回缺少这些字段时，本版会拒绝广播。不要为让它下单而删除检查。**

## 底仓管理

- 付费币尚未实际回本时，保留现有风险退出。
- 实际净收入覆盖成本及费用后，将该时点剩余数量的 50% 固定为底仓，只划分一次。
- 10／20 倍分批止盈，以及普通回撤退出，只处理交易仓。
- 免费代币保留原始到账数量的 30%，其余部分执行回撤退出。
- 24／48 小时只提醒复盘，不因到点自动卖出底仓。
- 交易仓卖完仍继续追踪底仓；安全退出或明确的全卖请求可以包含底仓。
- 部分成交按已经固定的卖出目标累计，重启不会重复划分或重卖同一阶段。

查看仓位 ID：

~~~sh
node src/cli.mjs status
~~~

本程序停止后，可以写入明确的全卖请求：

~~~sh
node src/cli.mjs request-sale "钱包地址:代币地址" --all
~~~

随后先用观察模式查看计划。只有完成兼容验证、显式设置 mode=live，并使用 watch --execute 启动的通道才可能真实广播。外部转账／补铸导致数量不一致时会暂停，不能自动重置成本和底仓。

## 首版的实际边界

- 发现范围是逐块部署、成功的 ERC20／ERC721 铸造事件、Agent ID 登记合约关联。并不保证覆盖后端签名、所有工厂／CREATE2／跨链项目或全链无遗漏。
- 自动参与仅支持本地审核过的固定调用。未知函数、动态邀请参数、白名单签名、通用交易照抄、自动扩份均不执行。
- 退款语义需要本地人工代码审核。程序不会仅因发现 refund 函数就放行，也不能自动证明未来一定能退款。只做核验和期限提醒，没有自动退款。
- 目前只有经过约束的 PancakeSwap V2 路由；V3／Infinity／其他 DEX 的自动卖出和完整开池检测尚未实现。没有可验证路由时只告警，不会调用不明路由。
- BNB 价格目前使用指定 V2 路由，不是多源抗操纵价格预言机。低流动性、突发价格变化仍可能造成漏单或拒绝计划。
- 没有自动 BNB 换 USDT，USDT 不足时会提示；不会为凑余额额外下单。
- 真实广播协议、Windows 上的官方钱包 CLI、多钱包实例和智能账户／打包交易回执还需要逐项验证。回执不匹配时保持锁定，不猜测成功。
- 需要新状态文件；不会自动覆盖或导入上游 watch_state.json。没有成本及交易证据的旧仓位不能自动迁移为“已回本”。
- 发现合约升级／资产代码变化时先暂停并告警，不能承诺已经变成貔貅的资产还能卖出。
- 没有接入 MEV 私有广播，也没有自动判断多个地址由同一人控制的能力。

完整攻击面与当前覆盖程度见 [安全说明](SECURITY.md)，模块结构见 [开发说明](docs/development.md)。
