# 上游 v2.7.6 与 Radar beta.2 对比

核对日期：2026-11-01，北京时间。对比基线为本仓库 beta.1，上游固定在提交 [8f9c488](https://github.com/nancyc0813-maker/agentid-sniper/tree/8f9c488f064e8cdbc9e46df4905bfb25a6a7af00)，不代表其后续版本。上游相对最初参考的 v2.6.5 增加了 16 次提交。

结论：上游的发现渠道、通用铸造适配和使用入口更完整；Radar 的固定模板、预算日记、预期资产绑定与独立底仓规则约束更明确。Radar 仍是开发预览，未进行真实钱包广播验证，不能据此宣称整体更好、更安全、收益更高，或已能替代上游实盘流程。此次比较是静态代码检查与 Radar 离线测试，不是两个工具的实盘对照试验。

## 对比

| 项目 | 上游 v2.7.6 | Radar beta.2 |
| --- | --- | --- |
| 项目发现 | 链上扫描、可选 TG 群／重点群、热门网址提取及名称匹配，覆盖更广 | 受限链上发现；尚无 TG 入站或网页抓取 |
| 自动适配 | 有跟单调用、地址／份数替换、付款类型学习和涨价重试 | 仅审核后的固定模板，容易漏掉未适配项目 |
| 新项目排队 | 热门快速检查，普通队列只轮当天加入的项目 | 借鉴优先级和有界检查；不活跃项目降频，仍保留复查 |
| 人数与进度 | 正常付费路径要求 60% 和 100 个 Agent ID 发送者；未知进度有热度回退 | 付费要求 60%、100 个已验证发送者及近期热度；未知进度额外要求模板显式允许 |
| 退款 | 正常付费路径已取消退款为必要条件，改查钱包／每笔额度限制 | 仍要求本地审核的退款条款、代码身份、资金覆盖和期限；不能保证将来退款 |
| 付费 NFT | 可以参与，另有 70%、150 人、钱包限额、10U 预算与图片检查 | 自动参与关闭；真实图片和人数都不能保证 NFT 价值 |
| 预算 | 正常每钱包付费日额度 60U、单项目 20U；跟单涨价路径可只把基础金额计入日额度 | 所有钱包共享预算，完整付款和 Gas 预占，未确认持续占用，没有涨价豁免 |
| 防卖飞 | 已新增回本后剩余数量 20% 长抱、交易部分回撤阈值 60% | 已有付费实际回本后锁定剩余数量 50%、免费原始数量 30% 底仓；不是这次新增 |
| 其他 DEX | DexScreener＋GeckoTerminal 发现；部分估值使用第三方展示价 | 新增可选 DexScreener 收录提醒与新铸造否决；交易仍仅受限 V2，展示价不进入卖出决策 |
| 验证程度 | 本次未运行其钱包或安装流程，不能验证真实成功率 | 75 项离线测试，仍无真实钱包兼容或收益验证 |

上游代码根据用户偏好频繁修改；部分注释沿用旧值，不能把注释当成当前行为。上述结论以实际分支和常量为准。强制参与路径还有不同例外，本版没有移植这些例外。

## 这次采用的改进

1. 新项目优先、近门槛／高热度快速检查、旧项目降频。每轮最多 8 个模板，并发最多 2 个，普通队列保留名额；没有把所有老项目永久丢弃。持仓、退款、未确认订单和授权清理独立运行。
2. 已验证发送者计热度。修正 beta.1 中 burstCount 会混入普通地址的问题；不以空投接收者计人数，重复发送者只计一次。付费进度达标也不能代替人数门槛。
3. 可选的其他 DEX 池子观察。固定公开接口、只查确切 BSC 代币、限速缓存；有池子可以否决新铸造，没有收录仍不能证明无池子。只提醒，不以展示价触发卖出。

## 未采用的变更

- 取消退款检查、开放付费 NFT：不符合本版对付费诱导的防护目标。
- 跟单参数猜测、自动改份数与涨价：本版没有足够的参数语义审核和真实交易证明。
- 把涨价部分从日额度中剔除：预算应覆盖完整付款。上游当前重试数组实际包含 +2%、+5%、+10%、+20%，不能只看相邻的“最多 10%”旧注释。
- TG 群名关键词直接提权、热门网址自动匹配成可付款模板：来源热度只适合排序，不能代替合约审核；本版尚未实现该类输入适配。
- 用第三方标价估算可成交净额：开池提醒和可执行路由报价是不同证据，本版继续要求受限路由和 minOut。

## 会不会漏项目

会。固定模板、退款、人数与价格有效期本来就会排除一部分机会。此版的人数来自程序运行时捕捉到的成功交易，不是全链完整历史统计；冷启动尤其需要积累。改善排队可以减少检查太慢造成的遗漏，不能保证参与成功，也不能填补未知 ABI、后端签名或不支持的路由。

长期仓位比例更高可能减少卖飞，也可能保留更多后来归零的仓位。没有逐笔真实数据，不能断言哪组止盈参数收益更高。
